DESIGN.md System Guide

Claude Code 팀 시스템에서 `DESIGN.md`가 어떤 역할을 맡는지 학습하는 시각 가이드입니다. `CLAUDE.md`는 작업 방식, `DESIGN.md`는 시각 시스템을 고정합니다. 이 둘을 분리하면 에이전트가 UI 작업마다 같은 기준을 재탐색하지 않고 토큰, 컴포넌트, 반응형 규칙을 일관되게 적용할 수 있습니다.

주입 흐름 보기 용어 검색
CLAUDE.md

권한, 명령, 검증, 팀 운영 규칙. 에이전트가 어떻게 일할지 정의합니다.

DESIGN.md

색상, 타이포그래피, spacing, radius, 컴포넌트, 금지 패턴을 정의합니다.

↓ 토큰과 화면 계약으로 연결
UX_CONCEPT / IA

사용자 맥락, 정보 구조, 화면 간 이동을 고정합니다.

UI_SPEC

화면별 레이아웃, 상태, 인터랙션, 접근성 요구를 구현 계약으로 만듭니다.

주입 파이프라인

신규 프로젝트와 기존 프로젝트 모두 같은 흐름을 사용합니다. 차이는 2단계에서 기존 토큰을 추출하느냐, 새 방향을 설계하느냐입니다.

1맥락 확인제품 유형, 사용자, UI 변경 범위, 기존 UX 문서를 확인합니다.
2토큰 조사CSS 변수, Tailwind theme, 컴포넌트 스타일에서 현재 값을 수집합니다.
3DESIGN.md 작성YAML token과 Markdown rationale을 함께 작성합니다.
4규칙 연결`CLAUDE.md` 또는 rules에서 UI 작업 전 DESIGN.md를 읽게 합니다.
5검증 기록체크리스트, lint 결과, version note를 완료 기록에 남깁니다.

토큰 구조

Google `design.md` 방식은 앞쪽 YAML이 기계 판독용 값, 뒤쪽 Markdown이 적용 이유입니다. Claude는 값과 이유를 같이 읽을 때 UI 일관성이 좋아집니다.

---
version: "0.1.0"
name: "Project"
colors:
  primary: "#111827"
  accent: "#2563EB"
typography:
  h1:
    fontFamily: "Display Font"
    fontSize: "2.5rem"
rounded:
  md: "8px"
components:
  button-primary:
    backgroundColor: "{colors.accent}"
    rounded: "{rounded.md}"
---

## Components
Primary CTA는 화면당 1개만 사용한다.
  • Token: 에이전트가 그대로 재사용할 수 있는 값입니다.
  • Rationale: 값이 왜 존재하고 언제 써야 하는지 설명합니다.
  • Reference: `{colors.accent}`처럼 토큰 간 연결을 명시합니다.
  • Version: 디자인 계약 변경 이력을 프로젝트 내부에서 관리합니다.
