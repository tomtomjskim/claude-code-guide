# Multi-Agent Team System v4.3 Changelog

**Release Date**: 2026-05-12
**Upgraded From**: v4.2 (2026-05-04, DESIGN.md 운영 모델)

---

## Summary

v4.3은 **PDARR + Goal-runtime 정렬** 릴리즈이다. 코드 에이전트(Claude Code 등)에 `/goal` 패러다임이 도입되면서 "1 기능 = 1 Goal = 빌드/테스트/시각확인 1 루프" 단위 실행이 표준이 되었다. v4.3은 이 단위 실행이 잘 흐르도록 PDARR 사이의 빈 자리를 메우고, 비기술/바이브코더 진입점을 보강한다.

핵심 변화:
- `/breakdown` 스킬 신규 — PRD를 기능 단위로 분해 + 우선순위 + 의존성 그래프 + Goal 실행 순서 결정
- `/prd --vibe` 모드 신규 — 한 문장 아이디어부터 인터뷰(5세트) + WebSearch(2 batch)로 PRD 자동 채움
- PDARR Flow에 `/breakdown`과 `/goal` 단위 실행 옵션 명시
- show-me-the-prd 패턴 흡수, 단 PDARR 1문서 원칙 유지(4문서 분리 거부)

## /breakdown 스킬

**위치**: `/prd` ↔ `/analyze` 사이 (선택적)

**역할**: PRD에 기능이 2개 이상일 때, Goal 단위 실행을 위한 사전 분해.

**산출물**: `docs/prd/{프로젝트}/breakdown.md`
- 기능 표 (ID, 이름, 우선순위, 복잡도, 의존성, Goal 후보 ✅/❌)
- 기능 상세 (수용 기준, 복잡도 근거)
- 의존성 그래프 + 병렬 가능 그룹
- Goal 실행 순서 권고 (P0 우선 → 독립 기능 우선 → 복잡도 낮은 순)
- 진입 게이트 체크리스트

**핵심 안티패턴 차단** (SKILL.md 명시):
- "DB 스키마 추가"만 단독 기능 (사용자 가치 없음 → 흡수)
- "백엔드 API + 프론트 화면" 1 기능 묶기 (Goal 1 루프 초과 → 분리)
- "리팩터링" 등재 (별도 트랙)

**의존성 표기 원칙**: 데이터/UI 의존성만 인정. "먼저 하고 싶다"는 우선순위로만 표기.

## /prd --vibe 모드

**활성 조건**: 명시적 플래그. 자동 감지 ❌.

**기본 모드 보호**: 기본 `/prd`는 한 글자도 변경 없음 — 시니어/도메인 전문가 사용자 영향 0.

### 5-Step 인터뷰 워크플로우

| Step | 인터뷰 | 리서치 |
|------|--------|--------|
| 1. 아이디어 정의 | Q1-Q4 (개방형 1 + 객관식 3) | — |
| 2. 기능 선정 | Q5-Q6 | WebSearch Batch 1 (도메인) |
| 3. 데이터 모델 확인 | Q7 | — |
| 4. 기술 스택 | Q8-Q9 | WebSearch Batch 2 (스택) |
| 5. PRD 자동 채움 | — | (`--thorough`일 때만 추가 2 batch) |

### 비용 가드레일

| 모드 | 인터뷰 | WebSearch | 시간 | 추가 토큰 |
|------|--------|-----------|------|-----------|
| `--vibe --quick` | 5세트 | 0 batch | ~3분 | ~5K |
| `--vibe` (기본) | 5세트 | 2 batch | ~5-8분 | ~15-20K |
| `--vibe --thorough` | 5세트 | 4 batch | ~10-15분 | ~30-40K |

### show-me-the-prd 대비 차이

| 항목 | show-me-the-prd | `/prd --vibe` |
|------|-----------------|---------------|
| 산출물 | 4문서 (PRD/DATA_MODEL/PHASES/PROJECT_SPEC) | PRD 1문서 (PDARR 템플릿) |
| Phase 분리 | 자체 생성 | `/breakdown`에 위임 |
| DB 스키마 | 자체 작성 | `/spec`에 위임 |
| WebSearch batch | 4 (고정) | 2 기본, `--thorough`만 4 |
| 분기 | 단일 모드 | 4모드 (기본/--vibe/--vibe --quick/--vibe --thorough) |

PDARR의 `/prd → /breakdown → /spec → /goal` 분리 원칙을 지키기 위해, vibe 모드는 PRD 작성까지만 책임진다.

### 인터뷰 옵션 작성 규칙

매 옵션에 4요소 강제:
- 정의 (한 문장)
- 장점
- 단점
- 난이도 라벨 (`간단해요` / `좀 복잡해요` / `많이 복잡해요`)

추천안은 첫 번째 위치 + `(추천)` 라벨. 기술용어 금지(OAuth → "소셜 로그인").

## PDARR Flow 갱신

```
/dispatch → /prd → /breakdown → /analyze → /spec → /run (또는 /goal 단위) → /check-code → /reflect → /complete → /stage
```

- `/breakdown`은 PRD에 기능 ≥2개일 때만. 1 기능이면 생략.
- `/run`(레이어 분해 구현) vs `/goal`(1 기능 단위 빌드/테스트/시각확인 1 루프)은 다른 단위. 사용자가 선택.

## Migration

기존 사용자에게 필수 migration 없음. 두 변경 모두 추가만 하고 기존 흐름은 보존.

```bash
# 신규 스킬 설치 (기본 워크플로우 영향 없음)
bash scripts/install-skills.sh --skills breakdown /path/to/project

# 또는 전체 재설치
bash scripts/install-skills.sh --force /path/to/project
```

`--vibe`는 `/prd` 같은 스킬 안에 있으므로 별도 설치 불필요.

## Out of Scope

- `/goal` 스킬 자체는 코드 에이전트(Claude Code 등) 내장 기능이므로 본 레포에서 정의/구현하지 않음
- show-me-the-prd의 4문서 분리 모델 흡수 (PDARR 1문서 원칙과 충돌하므로 거부)
- vibe 모드 자동 감지 (오탐 위험으로 명시 플래그만 허용)
- `/breakdown`의 자동 의존성 사이클 해결 (사용자 확인 필요한 영역)
