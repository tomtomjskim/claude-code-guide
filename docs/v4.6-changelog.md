# Multi-Agent Team System v4.6 Changelog

**Release Date**: 2026-06-19
**Upgraded From**: v4.5 (2026-06-15, Agent Operating Kernel adapter)

---

## Summary

v4.6은 **Codex App instruction/hook hardening parity** 릴리즈이다. Claude Code의 memory/rules/hooks 분리 원칙을 Codex App/CLI의 `AGENTS.md`, `.codex/agents/*.toml`, `.codex/hooks.json`, trusted project scope 운영에 대응시킨다.

핵심은 전역 프롬프트를 길게 만드는 것이 아니라 레이어를 분리하는 것이다.

- 전역 지침: 개인 응답 성향과 안전 기본값
- 프로젝트 지침: 스택, 테스트 명령, 승인 기준
- custom agent: 역할, 적용 범위, 도구 fallback, 반환 계약
- hooks/permissions: 기계적으로 판별 가능한 차단/검증

## Key Decisions

### `codex-rescue`는 공식 plugin agent 우선

`codex@openai-codex` 플러그인이 `codex:codex-rescue`를 제공하는 경우 같은 이름의 local `.toml` agent를 만들지 않는다. output 누락 방지는 전역 `AGENTS.md`의 output contract로 처리한다.

### Trusted scope는 단계적으로 줄인다

권장 단계:

1. Stage A: 현 상태 관찰
2. Stage B: home directory 전체 trust 제거
3. Stage C: parent dev directory trust 제거, explicit repo만 유지

### Hook은 project pilot 후 승격한다

전역 hook을 바로 만들지 않는다. 기존 hook이 있는 repo에서 먼저 pilot하고, false positive를 확인한 뒤 boilerplate로 승격한다.

---

## Migration

필수 migration 없음.

Codex App/CLI를 함께 쓰는 프로젝트는 다음 순서로 선택 적용한다.

1. 전역 `AGENTS.md`를 짧게 유지한다.
2. 프로젝트 `AGENTS.md`에 테스트/승인/보안 정책을 둔다.
3. custom agent에는 `Applicability`, `Tool Preflight`, `tool_limitations`를 추가한다.
4. broad trusted scope를 Stage B부터 줄인다.
5. hook은 한 repo에서 pilot 후 승격한다.
