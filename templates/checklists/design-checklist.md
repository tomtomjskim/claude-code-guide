# 설계 검수 체크리스트

## 1. 요구사항 반영
- [ ] 모든 기능 요구사항이 설계에 반영되었는가?
- [ ] 비기능 요구사항(성능, 보안 등)이 고려되었는가?
- [ ] 예외 케이스 처리가 설계되었는가?

## 2. 아키텍처
- [ ] 전체 구조가 명확한가?
- [ ] 컴포넌트 간 의존성이 적절한가?
- [ ] 기존 아키텍처와 일관성이 있는가?
- [ ] 확장성이 고려되었는가?

## 3. 인터페이스 정의
- [ ] API 엔드포인트가 정의되었는가?
- [ ] 요청/응답 형식이 명확한가?
- [ ] 에러 응답이 정의되었는가?
- [ ] 타입/인터페이스가 정의되었는가?

## 4. 데이터 모델
- [ ] 엔티티/스키마가 정의되었는가?
- [ ] 관계가 명확한가?
- [ ] 인덱스 필요성이 검토되었는가?

## 5. 에러 처리
- [ ] 에러 코드가 정의되었는가?
- [ ] 에러 메시지가 사용자 친화적인가?
- [ ] 복구 가능한 에러와 치명적 에러가 구분되었는가?

## 6. 보안
- [ ] 인증/인가가 고려되었는가?
- [ ] 입력 검증이 계획되었는가?
- [ ] 민감 데이터 처리가 고려되었는가?

## 7. 성능
- [ ] 예상 부하가 고려되었는가?
- [ ] 캐싱 전략이 있는가?
- [ ] 쿼리 최적화가 고려되었는가?

## 8. UI/UX (해당 시)
- [ ] 화면 구조가 명확한가?
- [ ] 사용자 흐름이 자연스러운가?
- [ ] 반응형 디자인이 고려되었는가?
- [ ] 접근성이 고려되었는가?

## 9. 테스트 계획
- [ ] 테스트 범위가 정의되었는가?
- [ ] 테스트 케이스가 식별되었는가?

## 10. 문서화
- [ ] 다이어그램이 적절히 사용되었는가?
- [ ] 복잡한 로직이 설명되었는가?
- [ ] 결정 사항과 이유가 기록되었는가?

## 검수 결과

### 승인 조건
- 모든 필수 항목이 충족됨
- 중요 이슈가 없음
- 구현 가능성 확인됨

### 피드백 형식
```
## 검수 결과: [승인 / 수정 요청]

### 긍정적 측면
- ...

### 수정 필요 사항
- [ ] ...

### 권장 사항 (선택)
- ...
```
