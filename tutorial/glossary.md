# 용어 사전

## 기본 용어

### Git
**문서의 "버전 히스토리"** (구글 독스처럼)

모든 변경 기록을 추적합니다. 실수하면 이전 버전으로 돌아갈 수 있습니다.
| 구글 독스 | Git |
|-----------|-----|
| 자동 저장 | `commit` (의도적 저장 + 메모) |
| 버전 기록 보기 | `git log` |
| 이 버전으로 복원 | `git checkout` |

### Commit (커밋)
**"저장 + 메모 남기기"**

파일을 저장하면서 "뭘 바꿨는지" 메모를 남기는 것.
예: "로그인 버그 수정" 이라는 메모와 함께 저장.

### Branch (브랜치)
**"원본 복사해서 따로 작업하기"**

원본 문서를 건드리지 않고 복사본에서 실험.
잘 되면 원본에 합치고(merge), 안 되면 버리면 됨.

### Repository (레포지토리)
**"프로젝트 폴더 + 변경 기록 전체"**

코드 파일들과 모든 변경 히스토리를 담은 보관소.

## Claude Code 용어

### CLAUDE.md
**"AI 팀원에게 주는 업무 가이드"**

새 팀원에게 "우리 팀 규칙 문서"를 주듯이, AI에게 프로젝트 규칙을 알려주는 파일.
이게 있으면 AI가 프로젝트를 이해하고 일관되게 일합니다.

### MCP (Model Context Protocol)
**"외부 전문가 연결 전화번호"**

Claude Code가 외부 도구(DB, 코드 분석기 등)에 접근하는 방법.
전화번호부에 전문가를 등록하면, 필요할 때 전화해서 도움받는 것과 같음.

### Agent (에이전트)
**"특정 분야 전문 담당자"**

PM(기획), Developer(개발), QA(검수) 등 각자 전문 분야가 있는 AI 담당자.
사람 팀처럼 역할을 나눠서 일합니다.

### Slash Command (슬래시 커맨드)
**"자동화된 업무 절차"**

`/dispatch`, `/run`, `/check-code` 같은 명령어.
버튼 하나 누르면 정해진 절차가 자동으로 실행되는 것과 같음.

## 워크플로우 용어

### PDARR
**"프로젝트 관리 5단계"**

| 단계 | 뜻 | 회사에서 | Claude Code |
|------|-----|---------|------------|
| **P**lan | 계획 | 기획 회의 | `/prd`, `/analyze` |
| **D**ocument | 문서화 | 설계 문서 | `/spec` |
| **A**ct | 실행 | 개발 | `/run` |
| **R**eview | 검토 | 코드 리뷰 | `/check-code` |
| **R**eflect | 회고 | 회고 미팅 | `/reflect` |

### /dispatch
**"접수처에 업무 요청"**

업무를 맡기면 복잡도를 판단해서 적절한 경로로 안내.
- 간단한 일 → 바로 처리
- 복잡한 일 → 분석부터

### Preset (프리셋)
**"업무 강도 조절 다이얼"**

| 다이얼 | 의미 | 사용 시점 |
|--------|------|----------|
| `--quick` | 빠르게 훑기 | 작업 중 간단 체크 |
| standard | 보통 (기본) | 일반적인 상황 |
| `--thorough` | 꼼꼼하게 | 중요한 변경 전 |
| `--team` | 팀 전체 투입 | 대규모 작업 |

### Handoff (핸드오프)
**"업무 인수인계"**

에이전트 A가 작업을 마치고 에이전트 B에게 넘기는 것.
"여기까지 했고, 이런 걸 발견했고, 이렇게 하면 좋겠다"는 구조화된 인계.

### Tiebreaker (타이브레이커)
**"의견 충돌 시 중재자"**

여러 리뷰어의 의견이 다를 때, 규칙에 따라 중재하는 시스템.
보안 > 성능 > 유지보수 > 스타일 순으로 우선순위 적용.

## 기술 용어 (개발자 레벨)

### API (Application Programming Interface)
**"식당 메뉴판 + 주문 시스템"**

프로그램끼리 소통하는 규격.
메뉴(엔드포인트)에서 원하는 걸 주문(요청)하면 음식(데이터)이 나옴.

### REST API
**"HTTP 주소 기반 API"**

```
GET  /api/users      → 사용자 목록 보기
POST /api/users      → 새 사용자 등록
DELETE /api/users/3   → 3번 사용자 삭제
```

### JSON
**"데이터를 주고받는 표준 형식"**

```json
{
  "name": "홍길동",
  "age": 30,
  "hobbies": ["독서", "코딩"]
}
```
사람이 읽기도, 컴퓨터가 읽기도 쉬운 형식.

### Token (토큰)
**AI 맥락에서는 "글자 수 단위"**

Claude가 처리하는 텍스트의 단위. 대략 한국어 1글자 ≈ 1~2 토큰.
`--team`이 토큰을 많이 쓰는 이유: 여러 에이전트가 각각 분석하니까.
