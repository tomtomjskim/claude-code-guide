# 미션 1: 커스텀 에이전트 만들기 — "나만의 전문가 정의"

> 예상 소요: 15분 | 난이도: ★★★★☆

## 목표
5-Section 템플릿으로 프로젝트에 특화된 에이전트 프롬프트를 작성한다.

## 배경
기본 제공 에이전트(PM, Developer, QA 등)로 부족한 경우,
**도메인 전문가 에이전트**를 직접 만들 수 있습니다.

예시:
- 이커머스 프로젝트 → "결제 전문가" 에이전트
- 의료 프로젝트 → "HIPAA 컴플라이언스 검사관" 에이전트
- 게임 프로젝트 → "밸런스 분석가" 에이전트

## 실습: "API 테스터" 에이전트 만들기

### Step 1: 템플릿 확인
```
templates/prompts/TEMPLATE.md 파일을 보여줘.
5-Section 구조가 뭔지 설명해줘.
```

5-Section 구조:
```
1. Opening      — 역할과 정체성 ("당신은 ~입니다")
2. Working Mode — 작업 방식 ("먼저 ~하고, 그다음 ~")
3. Focus On     — 집중 포인트 ("특히 ~에 주의")
4. Quality Checks — 완료 전 체크리스트
5. Return/Boundary — 산출물 형식 + 범위 제한
```

### Step 2: 에이전트 작성 요청
```
templates/prompts/TEMPLATE.md 구조를 따라서
"API 테스터" 에이전트 프롬프트를 만들어줘.

역할: api-service의 모든 엔드포인트를 테스트하는 전문가
작업 방식:
  1. API 엔드포인트 목록 파악
  2. 각 엔드포인트에 대해 정상/에러 케이스 테스트 스크립트 생성
  3. 엣지 케이스 (빈 값, 특수문자, 큰 데이터) 테스트
집중: 응답 코드, 에러 메시지 일관성, 입력 검증
산출물: 테스트 결과 리포트 (통과/실패 목록)
범위: 구현 수정은 하지 않음, 테스트와 리포트만
```

### Step 3: 에이전트 테스트
만든 프롬프트를 실제로 사용해봅니다:
```
방금 만든 API 테스터 프롬프트를 사용해서 api-service를 테스트해줘
```

### Step 4: 개선
결과를 보고 프롬프트를 개선합니다:
```
테스트 결과가 너무 길어. Quality Checks 섹션에
"리포트는 30줄 이내로 요약" 조건을 추가해줘
```

## 성공 기준
- [x] 5-Section 구조를 이해함
- [x] 커스텀 에이전트 프롬프트를 작성함
- [x] 실제로 사용해보고 개선점을 발견함

## 핵심 포인트
- **Opening**이 가장 중요 — 역할이 명확해야 일관된 결과
- **Boundary**를 반드시 설정 — "하지 말아야 할 것"을 명시하지 않으면 범위 이탈
- 기존 에이전트(`templates/prompts/`)를 참고하면 패턴이 보임
- 반복 사용할 에이전트는 `templates/prompts/`에 저장
