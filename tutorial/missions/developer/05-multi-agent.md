# 미션 5: 멀티 에이전트 체험 — "팀으로 일하기"

> 예상 소요: 10분 | 난이도: ★★★★☆

## 목표
`--team` 프리셋으로 여러 AI 전문가가 협업하는 과정을 체험한다.

## 배경

### 멀티 에이전트란?
하나의 큰 프로젝트를 혼자 하면 한계가 있습니다.
실제 회사에서는 여러 전문가가 역할을 나눠 일합니다:

```
큰 프로젝트 → PM이 분석 → 설계자가 설계 → 개발자가 구현 → QA가 검수
```

Claude Code의 `--team` 모드도 마찬가지입니다:
```
--team 요청 → PM(분석) → Architect(설계) → Developer(구현) → QA(검수)
```

### 에이전트 종류
| 역할 | 하는 일 | 사람으로 치면 |
|------|---------|-------------|
| PM | 요구사항 분석, 작업 분해 | 프로젝트 매니저 |
| Explorer | 기존 코드 조사 | 시니어 개발자 (코드 파악) |
| Architect | 구조 설계 | 설계자/아키텍트 |
| Developer | 코드 구현 | 개발자 |
| QA | 품질 검수 | 테스터 |

## 실습: api-service에 팀 분석 요청

### Step 1: 팀 분석
```
/analyze --team api-service에 인증(authentication) 시스템을 추가하려면 어떻게 해야 할까?
JWT 토큰 기반으로 로그인/회원가입 API를 만들고, 기존 API에 인증 미들웨어를 적용하고 싶어.
```

→ 여러 에이전트가 각자 관점에서 분석:
- PM: 요구사항 정리, 작업 분해
- Explorer: 기존 코드 구조 파악
- Architect: 시스템 설계 방향

### Step 2: 팀 코드 리뷰
```
/check-code --team api-service
```

→ 전문 리뷰어들이 각자 관점에서 코드 검수:
- Security Sentinel: "토큰 저장 방식이 안전한가?"
- Performance Prophet: "요청이 많아지면 괜찮은가?"
- Code Reviewer: "코드 구조가 깔끔한가?"

### Step 3: 리뷰 결과 확인
각 리뷰어의 의견이 다를 수 있습니다.
의견이 충돌하면 **Tiebreaker Protocol**이 중재합니다:
```
1. 투표 → 2. 기준 적용 → 3. 에스컬레이션 → 4. PM 최종 판단
```
