# 미션 4: 프리셋 활용 — "업무 강도 조절하기"

> 예상 소요: 5분 | 난이도: ★★★☆☆

## 목표
프리셋(--quick, standard, --thorough, --team)의 차이를 체험하고 적절히 선택한다.

## 배경

### 프리셋이란?
같은 업무도 상황에 따라 깊이가 다릅니다:

```
보고서 검토 요청:
  "대충 훑어봐줘"     → --quick   (1분)
  "검토해줘"          → standard  (5분)
  "꼼꼼히 봐줘"       → --thorough (15분)
  "팀 전체가 리뷰해줘" → --team    (30분)
```

Claude Code도 동일합니다:
```
깊이:  --quick ← standard → --thorough
실행:  단일    ← 기본    → --team
```

## 실습

### Step 1: --quick 체험
```
/check-code --quick todo-app
```
→ 빠른 스캔. 주요 문제만 짚어줌. (문법, 명백한 버그)

### Step 2: standard 체험
```
/check-code todo-app
```
→ 일반 검수. 코드 품질, 패턴, 개선점 포함.

### Step 3: --thorough 체험
```
/check-code --thorough todo-app
```
→ 심층 검수. 보안, 성능, 접근성, 엣지 케이스까지.

### Step 4: 결과 비교
세 가지 결과를 비교해보세요:
- 발견한 이슈 수가 다른가?
- 분석 깊이가 다른가?
- 소요 시간이 다른가?

## 성공 기준
- [x] 3가지 프리셋을 모두 실행해봄
- [x] 각 프리셋의 분석 깊이 차이를 체감
- [x] 상황별 프리셋 선택 기준을 이해

## 프리셋 선택 가이드

| 상황 | 추천 프리셋 |
|------|-----------|
| 작업 중 빠른 체크 | `--quick` |
| 일반적인 개발 후 검수 | standard (기본) |
| PR 올리기 전 | `--thorough` |
| 배포 전 최종 검수 | `--team` |

### 안티패턴
- 매번 `--thorough` 사용 → 시간/비용 낭비
- 배포 전에 `--quick`만 → 위험
- 1~2개 파일 수정에 `--team` → 과도
