# 서브에이전트 사용 전략

## 핵심 원칙
- 서브에이전트 내부에서는 PreToolUse Hook이 적용되지 않는다
- 서브에이전트는 `.claude/rules/*.md`를 상속받지 않을 수 있다
- 따라서 서브에이전트에 위임할 때는 prompt에 필요한 규칙을 명시적으로 포함해야 한다

## 작업 유형별 실행 방식

### 메인이 직접 수행 (서브에이전트 금지)
- 파일 탐색, 코드 분석, 구조 파악 → Read/Grep/Glob 직접 사용
- 단일 파일 수정, 버그 수정
- 설정 파일 변경 (settings, config, env)
- 5줄 이하의 간단한 수정

### 서브에이전트 위임 허용
- 3개 이상 파일에 걸친 구현 작업
- 독립적인 병렬 작업 (빌드 + 테스트 + 린트 동시 실행)
- 장기 세션(20+ 턴)에서 컨텍스트 보호가 필요한 구현
- 명확한 스펙이 정의된 모듈 단위 작업

### 서브에이전트 위임 시 필수 사항
- prompt에 작업 범위를 명확히 한정한다 (파일 목록, 변경 범위)
- prompt에 "불필요한 탐색 금지, 지정된 파일만 수정"을 명시한다
- 결과물의 검증 기준을 prompt에 포함한다
- 프로젝트 규칙이 필요하면 prompt에 해당 규칙을 인라인으로 포함한다

## 토큰 효율 규칙

### 고정 오버헤드 인식
- 서브에이전트 1회 = **~14,000 tokens 고정 비용** (시스템 프롬프트 + 도구 스키마 + CLAUDE.md 중복)
- 파일 1-2개 작업은 메인이 직접 하면 5,000-8,000 tokens, 서브에이전트면 20,000+ tokens
- 고정 비용을 상회하는 작업량(파일 3개+)이 있을 때만 서브에이전트가 효율적

### 분할 전략
- 독립 작업 2-3개를 **하나의 서브에이전트로 합쳐서** 오버헤드를 1회로 줄인다
- "installer 수정 + docs 수정"처럼 공유 컨텍스트가 없어도 하나로 합칠 수 있다
- 병렬화가 필요한 경우에만 복수 서브에이전트를 사용한다 (예: 빌드 + 테스트 동시)

### 모델 라우팅
- 단순 편집/문서 수정: `model: "sonnet"` 지정 (비용 1/5)
- 복잡한 로직 구현: `model: "opus"` (기본값)
- 포맷팅/린트 수준: `model: "haiku"` (비용 1/15)

### 기타
- 5줄 이하 수정에 서브에이전트를 쓰지 않는다
- 동일 파일을 여러 서브에이전트가 중복 읽지 않도록 한다
- 서브에이전트에게 "간결하게 결과만 반환"을 지시한다
